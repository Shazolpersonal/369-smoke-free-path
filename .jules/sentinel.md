## 2025-02-14 - [Path Traversal / URL Bypass in Deep Links]
**Vulnerability:** URL validation logic relied solely on checking if a URL starts with `/` and not `//`. Attackers could bypass this check by providing a backslash `/\\` which many parsers treat as absolute path routing, leading to deep link hijacking and potential open redirect vulnerabilities.
**Learning:** Checking for `//` is insufficient as `/\` can also be treated as a valid scheme or domain separator in some URL parsers. Relying entirely on incomplete string matching to determine relative URLs can be dangerous.
**Prevention:** Consider more robust validation like `!url.startsWith('/\\')` or utilizing a proper URL parsing library to strictly validate relative-path properties and reject any un-intended schemas or domain resolutions.
## 2025-02-14 - [URL Encoding Bypass / DoS via URIError]
**Vulnerability:** The application mitigated deep link routing path traversal (e.g., `//` or `/\`) but was susceptible to an evasion where an attacker could URL-encode the backslashes/slashes (e.g., `/%2f` or `/%5c`). A naive fix to use `decodeURIComponent()` introduced a Denial of Service (DoS) vulnerability: passing malformed URL encoding sequences (e.g., a standalone `%`) would trigger an unhandled `URIError` and crash the application.
**Learning:** Security fixes must fail securely and not introduce new crash vectors. External user input passed to functions like `decodeURIComponent` must always be wrapped in a `try...catch` block.
**Prevention:** Always wrap `decodeURIComponent` in a `try...catch` block when handling unvalidated external URLs, falling back to an empty string or safe default on failure to prevent application crashes.
## 2025-02-14 - [Unhandled Promise Rejection in Clipboard API]
**Vulnerability:** Asynchronous calls to `Clipboard.setStringAsync` were not wrapped in a `try...catch` block. If the device clipboard API failed (e.g., due to OS restrictions, low memory, or permission changes), the unhandled promise rejection could cause the application to crash or expose internal state.
**Learning:** Even seemingly benign system APIs like the clipboard can fail. Leaving asynchronous operations unhandled violates the "fail securely" principle and introduces Denial of Service (DoS) vectors.
**Prevention:** Always wrap asynchronous system APIs (like `Clipboard.setStringAsync`) in a `try...catch` block. Fallback gracefully by alerting the user with a generic message and securely logging the actual error using the centralized logger.
## 2025-02-14 - [TOCTOU URL Validation Bypass in Deep Links]
**Vulnerability:** Deep link validation validated the decoded URL but then passed the original, encoded URL to the router. This Time-of-Check to Time-of-Use (TOCTOU) vulnerability allowed bypassing the validation if the router's internal decoding logic interpreted the original URL differently than the initial validation check.
**Learning:** Always use the exact validated/sanitized string when executing an operation, rather than relying on the downstream component to handle the original input identically.
**Prevention:** Push the validated, decoded string `decodedUrl` to the router rather than the original `url` string.
## 2025-02-14 - [Unhandled Promise Rejection in expo-notifications APIs]
**Vulnerability:** Asynchronous calls to `expo-notifications` APIs (like `getPermissionsAsync`, `requestPermissionsAsync`, `setNotificationChannelAsync`, `cancelAllScheduledNotificationsAsync`, and `scheduleNotificationAsync`) were not wrapped in a `try...catch` block. Unhandled promise rejections in these native module bindings could crash the application on devices where notification permissions are tightly restricted or if the native push service transiently fails.
**Learning:** Native module bindings that interact with device-level services can fail unexpectedly. Relying on them without error boundaries introduces Denial of Service (DoS) vectors.
**Prevention:** Always wrap asynchronous system or native module API calls in a `try...catch` block. Catching these errors ensures the app can fallback gracefully (e.g., silently disabling notifications instead of crashing) while securely logging the error for debugging.
